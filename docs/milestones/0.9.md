# Milestone 0.9 — Maintenance

**Branch:** `milestone/0.9-maintenance`
**Baseline:** HLAO 0.8 (`e427273`, `milestone/0.8-agent-at-birth`)
**Source:** internal module and test review. No new feature findings.

## Theme

No behavior change, no wire change, no new command, no new dependency. Reshape the modules
that grew through 0.6–0.8, remove duplicated logic and dead exports, make the test harness
stop re-declaring the protocol, and prune the ledger. Safety bounds and permission rules
(N-08 enforcement, N-10, N-11) move to 0.10.

This milestone is judged by what did **not** change: the CLI surface, JSON shapes, protocol
2.3, event names, exit codes, and the full test result.

## Decisions

### D1. Barrels keep the public surface stable

`src/protocol.ts`, `src/cli/commands/control.ts`, `src/cli/commands/prompts.ts`, and
`src/cli/commands/ops.ts` remain as thin re-export barrels. Every existing import site —
core, CLI, and tests — stays valid, so the split is reviewable as moved code rather than a
rename sweep. Submodules never import their own barrel; that rule keeps the graph acyclic.

### D2. Split by responsibility

- `protocol.ts` → `protocol/version.ts` (wire constants, capabilities, ACP version),
  `protocol/contract.ts` (types, method names, `isTerminalStatus`),
  `protocol/parse.ts` (boundary validation).
- `session.ts` keeps the `Session` state machine; its pure tail moves to
  `session/queue.ts`, `session/async.ts`, `session/process.ts`, `session/permissions.ts`,
  and `session/projection.ts`.
- `supervisor.ts` keeps the server; `supervisor/util.ts` (actor, path key, failure envelope,
  delay) and `supervisor/resolve.ts` (token resolution) are extracted.
- CLI command groups become one module per command. `session-view.ts` holds the shared
  display/terminal/resolve projections; `prompt-support.ts` holds bounded partial output.

The `Session` class body, supervisor spawn/dispatch, and the `parseParams` switch are left
intact. They share private state or are already cohesive; splitting them in a
behavior-freeze pass would trade one kind of complexity for another.

### D3. Deduplicate only exact duplicates

- Terminal status is one predicate, `isTerminalStatus`, in the protocol contract; the
  session, supervisor, list, selectors, render, and commands use it.
- The CLI's `displayStatus`/`isTerminal`/`resolveInList` live once in `session-view.ts`.
- Event titles and queue previews share one whitespace-collapsing helper.
- Tests import the wire result types instead of maintaining copies. `SessionValue` had
  already drifted (missing `createdAt`, `lastActivityAt`, exit state); aliases prevent that.

Subtly different formatters (display-width truncation, payload rendering, stderr line caps,
path prefix matching) are intentionally left alone. Merging them would change output.

### D4. No option-parsing framework

The `parseArgs → help → positionals → context → connect` preamble repeats, but the command
variations are real: some defer `connect`, some use selectors, some take no positional.
Abstracting it would add indirection without removing decisions. The shared helpers stay
`args.ts` and `context.ts`.

### D5. Dead exports are demoted, not preserved “just in case”

Unreferenced functions were removed (`jsonEnvelopeEnabled`, `jsonCommandName`,
`IPC_PROTOCOL_VERSION`, `isHlaoError`). Exports used only inside their declaring file lost
the `export` keyword (`ERROR_CODES`, `SESSION_ID_LENGTH`, `METHODS`, `formatTokens`,
`formatAge`, `describeTarget`, `AlreadyRunningError`, `SupervisorServer`). Types named in
`contracts/` remain exported.

## Out of scope

- Features of any kind, including the P0/P1/P2 findings that remain in the ledger.
- Wire additions or renames.
- New dependencies, formatters, linters, or bundlers.
- Splitting the `Session` state machine or the supervisor dispatch cluster.
