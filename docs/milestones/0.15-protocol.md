# HLAO wire protocol 3.0 — frozen for 0.15

**Frozen:** 2026-10-21. **Status:** authoritative for the 0.15 core and dashboard
implementations. Do not change a shape or a semantic below without the operator's approval.
**Milestone:** `docs/milestones/0.15.md`. **ADR:** `docs/adr/0013-provider-owns-permission-policy.md`.

HLAO no longer owns a permission policy. The provider's mode is the policy layer; every
provider permission request is relayed to the operator. This document freezes the wire, the
config keys, and the behaviors both implementations must match.

## Version and capabilities

```ts
WIRE_PROTOCOL_VERSION = { major: 3, minor: 0 };
```

Clients require major equality; there is no compatibility shim. Add capabilities:

```ts
"session.pendingPermissions";
"permit.request";
```

Keep every other capability. `hello` reports 3.0 and the expanded list.

## Removed

```ts
type PermissionPolicy;                     // "allow" | "ask" | "deny"
SessionView.permissionPolicy;
SessionView.pendingPermission;
SpawnParams.permissionPolicy;
SetPolicyParams; SetPolicyResult;
"sessions.set_policy";
"policy.changed";                          // event type
permission.requested.policy;               // event data
permission.requested.auto;                 // event data
PermitParams.always;
```

The `policy` CLI command, `--permission`, and the config key `permissionPolicy` are removed.
`permit --always` survives as a CLI option selector only.

## Changed and added shapes

```ts
interface SessionView {
  // removed above; this replaces the singular field
  pendingPermissions: PermissionView[];
  // ... every other 2.9 field unchanged
}

// PermissionView is unchanged:
interface PermissionView {
  requestId: string;
  toolCallId: string | null;
  title: string;
  kind: string | null;
  options: { optionId: string; name: string; kind: string }[];
  requestedAt: string;
}

interface SpawnParams {
  // permissionPolicy removed; everything else unchanged
  mode?: string; // operator-only; see below
}

interface PermitParams {
  sessionId: string;
  requestId?: string; // required when more than one request is pending
  optionId: string;   // always resolved by the caller/CLI
}

interface PermitResult {
  session: SessionView;
  requestId: string;
  optionId: string;
  by: string;         // "operator" for the relay
}

interface AgentView {
  // backends.list / agents
  defaultMode?: string;
}
```

`permission.requested` data:

```ts
{
  requestId: string;
  toolCallId: string | null;
  title: string;
  kind: string | null;
  options: { optionId: string; name: string; kind: string }[];
  outsideTurn: boolean;       // unchanged
  queuePosition?: number;     // 1-based, FIFO; present for a queued request
}
```

`permission.resolved` data:

```ts
{
  requestId: string;
  optionId: string | null;
  optionName?: string;
  by: string;                 // "operator" | "timeout" | "system" | provider-withdraw actor
  reason?: string;            // "timeout" | "queue_full" | "withdrawn" | ...
  note?: string;
}
```

## Method semantics

- `sessions.permit` — **operator-only**. A request with a `callerSessionId` is refused with
  `operator_only`. With no pending request: `no_pending_permission`. With multiple pending
  and no `requestId`: `bad_request` naming the request ids. With an unknown `requestId`:
  `no_pending_permission` carrying the pending ids. The operator's answer resolves the ACP
  request and records `by: "operator"`.
- `sessions.set_mode` — **operator-only**. Reads stay open through `sessions.get`.
- `sessions.spawn` — `permissionPolicy` is gone. A `mode` supplied by a caller is refused
  with `operator_only`; an operator may supply it. The effective mode is the operator's
  `--mode` → the target backend's `defaultMode` → the provider's own default.
- `sessions.set_policy` — removed; a client calling it gets an unknown-method error.
- `sessions.list` / `sessions.get` — expose `pendingPermissions`; no policy field.
- `sessions.wait` — `until: "permission"` is satisfied when `pendingPermissions` is
  non-empty. `list --pending` matches the same condition. The session stays
  `waiting_permission` while any request remains.

## Queue and timeout rules

- Pending requests are a FIFO map keyed by `requestId`, bounded by
  `maxPendingPermissions` (default `16`, range `1..1000`), captured at spawn.
- A second concurrent request is queued. It is never auto-cancelled.
- Queue full: the new request is answered `cancelled` to the provider and recorded as
  `permission.resolved { by: "system", reason: "queue_full", optionId: null }`. It is not
  enqueued.
- `permissionTimeoutMs` (default `1800000`, `0` = park) starts one absolute one-shot deadline
  at `requestedAt` per request, captured at spawn. On expiry: select `reject_once`, else
  `reject_always`, else cancel; never an allow option; record
  `permission.resolved { by: "timeout", reason: "timeout", optionId }`. Clear the timer on
  answer, provider withdrawal, or close.
- `cancel` and `close` resolve every pending request as cancelled and clear the timers.
- Provider withdrawal clears only that request; the others remain.
- A provider request that arrives outside a turn (`outsideTurn: true`) follows the same
  queue and timeout rules.

## Config

```jsonc
{
  "permissionTimeoutMs": 1800000,   // 0 = park
  "maxPendingPermissions": 16,      // 1..1000
  "backends": {
    "claude": { "defaultMode": "auto" }
  }
}
```

- Removed: `permissionPolicy`.
- Added: `permissionTimeoutMs`, `maxPendingPermissions`, and `defaultMode` on a user or
  project backend manifest.
- An old `permissionPolicy` key is rejected with a migration message that names
  `defaultMode`, not the generic unknown-key error.
- A bad `defaultMode` name is the adapter's error, reported by the spawn; HLAO does not
  normalize mode names.

## Operator-only enforcement

The supervisor and the CLI both enforce it; the CLI's check is for a clear early message,
not the authority.

- Refused for a caller with `HLAO_SESSION_ID`: `sessions.permit`, `sessions.set_mode`, and a
  `mode` value on `sessions.spawn`. Error code `operator_only`.
- Allowed for a caller: `sessions.get`, `sessions.list`, `sessions.read`, `sessions.wait`,
  `sessions.send`, `sessions.cancel`, `sessions.close`, `sessions.rename`, prompt queue
  operations, spawn without `mode`/`permissionPolicy`, resume/fork, and all reads.
- An operator shell is a shell without `HLAO_SESSION_ID`; the dashboard is an operator
  client and must not send `callerSessionId`.
- This is advisory: caller identity is self-declared and the instance token is shared. The
  docs and skill must say so (N-08).

## CLI semantics fixed by this freeze

- `hlao spawn <backend> ... [--mode ID]` — `--permission` removed.
- `hlao mode [<id>] [modeId]` — read any; set operator-only. Bulk set with
  `--root`, `--tree`, `--status`, `--idle` (operator-only; replaces `policy` bulk).
- `hlao permit <id> [--allow | --deny | --option ID] [--always] [--request ID]` —
  operator-only. `--always` selects `allow_always` for `--allow`, `reject_always` for
  `--deny`; if the provider does not offer it, `bad_option` (no fallback). `--all-pending`
  and the existing selectors remain, operator-only.
- `hlao policy` — removed.
- `hlao config show` — prints `permissionTimeoutMs`, `maxPendingPermissions`, and each
  backend's `defaultMode`; no policy line.
- `hlao agents` — shows `defaultMode` when set.
- `get`/`list --wide`/`spawn` show the effective provider mode and the pending queue, never
  a policy.

## Startup and upgrade

- `probeSupervisor` must distinguish "not answering" from "alive, speaking major N."
  `client.ensureLock` and `Supervisor.#acquireLock` must refuse to start or replace a live
  supervisor with a different major, returning/printing `version_mismatch` with the upgrade
  instructions.
- `down` may use the legacy connection path to stop a running 2.x supervisor if that path
  works; otherwise the operator stops it with the old CLI. A 3.0 client never removes a live
  old-major lock as if it were a crash.
- A 2.x client connecting to 3.0 fails the major handshake; the dashboard is updated in
  lockstep.

## Responsibility split

**Core agent:** everything outside `dashboard/` — `src/`, `tests/`, `skills/`, `contracts/`,
`docs/`, `README.md`, `CHANGELOG.md`, `examples/`. Update `contracts/protocol.md` to this
freeze. Do not touch `dashboard/` or the root submodule pointer.

**Dashboard agent:** `dashboard/` only. Implement the 3.0 types and operator surfaces
(mode control, pending queue, default mode), remove policy UI, update the demo supervisor,
and keep its typecheck/tests/build green. Do not touch the root tree or commit the
submodule.

The parent integrates the dashboard pointer and runs the full suite after both agents
finish. Neither agent commits or pushes.
