# Milestone 0.14 — Mid-turn steering

**Branch:** `dev`
**Baseline:** `2cbbb0c` (the 0.13 acceptance fix)
**Source:** the 0.13 acceptance report, T33 / orchestration review.

## Theme

A session that messages a busy peer currently waits behind that peer's turn. For a long
task, the useful behavior is the opposite: a follow-up — a correction, a new constraint, an
answer that changes the plan — should reach the agent while it is still working. The ACP
steering extension (`_session/steering`) exists for exactly this, and the bundled
`claude-agent-acp` adapter advertises it.

0.14 makes steering the default for agent-to-agent messaging:

- A send to an idle target runs the prompt directly, as before.
- A send from a session to a busy target is injected into the running turn when the target
  adapter advertises steering; otherwise it queues.
- An operator shell keeps the observable queue behavior by default. `--steer` opts in and
  `--queue` forces the queue for either side.

The supervisor stays turn-serial. Steering is a provider request, not a second local turn:
HLAO creates no queue item and no turn number for it.

## Decisions

### D1. The default is a caller policy, not a supervisor default

The wire parameter `sessions.send.steer` defaults to false. The CLI chooses `true` when its
own `HLAO_SESSION_ID` is set (an agent caller). A pre-0.14 client therefore keeps exactly
the old queued behavior, and `send --steer` against a pre-0.14 supervisor is refused with
the usual capability hint instead of an unknown-field error.

### D2. Steering needs both an active turn and an adapter capability

`Session` records `InitializeResponse._meta.steering.supported` as
`SessionView.steeringSupported`. Injection is attempted only when the target has an active
turn and that flag is true. The request carries
`_meta.steering.idleBehavior: "promptRequired"` so a turn that ends between the local check
and the provider's check returns control instead of starting an untracked detached turn;
that outcome falls back to the ordinary queue. A JSON-RPC `methodNotFound` disables steering
for that session.

### D3. A steered message has no turn of its own

The adapter folds the prompt into the running turn. `prompt.steered` records the delivery
with the turn it joined; `prompt.sent` and a new turn number do not appear. `--wait` on a
steered send waits for that running turn to settle, because there is nothing else to wait
for. A self-send always queues: it is the documented deferred-next-turn form, and injecting
it into the turn that issued it can close a wait cycle.

### D4. The queue remains the only backlog

Steering does not grow `SessionView.queued`, does not appear in `hlao queue`, and is not
discarded by `cancel` beyond the running turn it joined. `cancel` stops the turn, and the
steered text goes with it.

## Wire changes — protocol 2.9 (additive)

- `SendParams.steer?: boolean`.
- `SendResult.steered?: boolean`.
- `SessionView.steeringSupported?: boolean`.
- Event type `prompt.steered` with `messageId`, `text`, `textPreview`, `textLength`, `from`,
  and the joined turn.
- Capability `send.steering`.

A 2.8 client that omits `steer` is unaffected.
