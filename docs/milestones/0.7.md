# Milestone 0.7 — Truthful and composable

**Branch:** `milestone/0.7-truthful-surface`
**Baseline:** HLAO 0.6.0 (`a6a27c5`, `milestone/0.6-stream-contract`)
**Source:** `FEATURE-REVIEW.md` and `FEATURE-REVIEW-0.5.md`, re-sequenced after 0.6.

## Theme

Every read says what is actually known, and every control can act on the set the operator
already sees. This is the truthfulness block the 0.5 review asked for, plus the two cheapest
job-shaped client assemblies. It adds no scheduler, store, registry, timer, or second
authority.

The 0.5 review proposed truthfulness as 0.5.1 and job control as 0.6. 0.6 became transport and
persistent streams instead. The credibility debt is therefore still open, and it is the
highest importance-to-complexity work available:

- A dry run that mutates, an `idle` that means "between turns", a documented export that saves
  one page, and a `down` that discards evidence are not missing conveniences. They make the
  readout untrustworthy, which is the product's whole claim.
- The control gaps are next: wait cannot express "finished or blocked or dead", and acting on
  a root/status set exists only on `close`.

Agent-at-birth, safety bounds, permission rules, resume after crash, and network surfaces are
deliberately deferred; each needs a design decision that would dominate this milestone.

## Decisions

### D1. `idle` stays precise; `settled` names completion

The wire's `idle` means "no active turn". It does not mean "finished", because a queue may
still be draining. Renaming it is a breaking wire change for a bug fix, so 0.7 is additive:

- `SessionView.settled` is `status === "idle" && queued === 0`.
- `sessions.wait` accepts `until: "settled"`, satisfied by settled, `waiting_permission`, or a
  terminal session. The result `reason` reports which of `idle`, `permission`, or `exit`
  matched.
- The CLI's `wait --until idle` maps to `settled`, and `list`/`close --status idle`/`--idle`
  treat an idle session with a non-empty queue as busy.
- `contracts/protocol.md` states the distinction explicitly. A client that needs the raw
  turn boundary asks for `idle`; a client that needs completion asks for `settled`.

This fixes every user-facing lie without breaking 2.1 clients. If the vocabulary proves
confusing, the wire can rename at 1.0; it does not need to happen here.

### D2. `nextSeq` is a real cursor

`since` is exclusive, so the cursor to pass back is the last **scanned** event's seq, not the
first unscanned event's. The current `nextSeq` skips one event whenever a page fills, and
`read --follow` inherits the skip. 0.7 fixes the arithmetic, updates the contract and unit
test, and uses the corrected cursor in `export` and the examples. This is a bug fix, not a
shape change.

### D3. The JSON envelope is opt-in

`--json=envelope` wraps a success as `{ ok: true, command, result }`; default shapes stay
unchanged until 1.0. The wrapper is centralized in `writeJson`, so every command is covered.
An ADR records the decision and the conformance test.

### D4. Selectors are client assemblies

`--root`, `--status`, `--idle`, and `--tree` on `wait`, `cancel`, `permit`, and `policy` are
implemented as `sessions.list` + existing methods in the CLI. No wire method grows a selector.
This preserves ADR 0007: a composite is a client assembly, not a core concept.

## Wire changes — protocol 2.2 (additive)

```ts
// SessionView additions
settled: boolean;                    // status === "idle" && queued === 0
lastEvent: {
  type: EventType;
  title: string | null;              // bounded, render-sanitized
  at: string;
} | null;

// sessions.wait params additions
until?: "idle" | "settled" | "permission" | "exit" | "change";
types?: EventType[];                 // only valid with until: "change"
grep?: string;                       // only valid with until: "change"

// supervisor.shutdown result
{ sessionsClosed: number; retainedDiscarded: number }
```

Capabilities: `wait.settled`, `wait.filters`, `session.settled`, `session.lastEvent`.

`until: "settled"` is satisfied by settled (idle with an empty queue), `waiting_permission`, or
a terminal session. The result and per-target `reason` report the matched condition
(`idle`, `permission`, or `exit`), not the word "settled". The existing `idle` condition keeps
its precise "no active turn" meaning.

## Tests

- A regression per P0 reproduction in the 0.5 evidence log, asserting state where the old bug
  was a mutation or a silent loss.
- Two queued prompts: `wait --until idle` (CLI) and `wait --until settled` (wire) both resolve
  only after turn 2; `wait --until idle` on the wire still reports the turn boundary.
- A 170-event session: `export` returns all 170, and a full forward page's `nextSeq` never
  skips an event.
- `down` with a retained failed session: warning and JSON both report it.
- Help grep test for removed scope language.
- Escape/bidi/CJK injection tests for `read`, `logs`, errors, and table alignment.
- Wait filter tests: `settled` with `types` is rejected; `change` with `types` matches only
  the filtered event.
- JSON envelope conformance for every command.
- The full unit, e2e, and acceptance suites stay green.

## Out of scope

- N-07 message identity/idempotency, N-08 spawn actor and scoped client, N-10 permission
  rules, N-11 resource bounds/budget, N-12 birth brief/ledger, N-13 attachments/system prompt,
  N-14 Unix tree kill. These belong to 0.8 ("agent at birth and reliability") and 0.9
  ("safety and policy").
- P0-14 resume after an adapter crash or supervisor restart; it needs ACP `session/load` and
  its own milestone.
- TCP opt-in, TLS, WebSocket and browser credentials, the dashboard/TUI/MCP surfaces. 0.6
  left these gated on a transport-policy decision.
- Changing the default `--json` shapes. The envelope is opt-in until 1.0.

## Acceptance

- `npm run check` clean; all suites green; protocol 2.2 in `hello` with the four new
  capabilities.
- Every P0 reproduction from `FEATURE-REVIEW-0.5.md` now behaves correctly, including the
  state-level assertions for dry-run, idle, export, and down.
- A job can be waited on by root/status without a shell loop, and a single session's state can
  be read without reading events.
- No new timer, store, registry, scheduler, or second authority was introduced.
