# Milestone 0.5 — Universal addressing

**Branch:** `milestone/0.5-universal-addressing`
**Baseline:** HLAO 0.4.0 (`1d9cecd`)
**Source:** the resume design discussion; `PRODUCT.md` Q6 is revised.

## Theme

One HLAO instance is one address space and one swarm boundary. Inside it, every session is
addressable by every caller. Isolation is deployment: run another `HLAO_HOME` with its own
supervisor, socket, and token. Everything inside an instance is semantic — naming, lineage,
agreements, roles, swarm membership — not enforced by core.

The token is the only hard boundary. A local process holding it is an operator; that was
already true. `callerSessionId` is attribution, not permission.

## Changes

- [x] `sessions.list` returns every session in the instance and no longer reports a `scope`.
      Its result is `{ sessions: SessionView[] }`.
- [x] Resolution checks existence and ambiguity only. A session may address its parent,
      siblings, cousins, and unrelated trees by id, unique name, or unique prefix.
- [x] The parent-send exception is removed; universal addressing subsumes it. ADR 0006 is
      superseded by ADR 0008.
- [x] `callerSessionId` remains in the envelope for attribution (`by`) and self-defaulting.
      A stale caller id does not make a request fail; it simply contributes no live session
      context.
- [x] `sessions.spawn.parentSessionId` may name any existing session. It records lineage and
      derives `rootId`/`depth`; it grants nothing. With no explicit parent, a live caller is
      the default; a stale caller produces a root.
- [x] `reload` and `shutdown` remain operator-only: they are instance operations, not session
      operations.
- [x] `forbidden` remains in the error taxonomy but no core session method emits it for scope.
- [x] Protocol version becomes `2.0`: removing `scope` and changing previously forbidden
      targets is breaking.
- [x] `HLAO_SESSION_ID` is still injected and still describes lineage. `HLAO_PARENT_ID`,
      `HLAO_ROOT_ID`, and `HLAO_DEPTH` remain context, not authority.

## Docs

- [x] `PRODUCT.md` Q6 is rewritten: universal addressing within an instance; the instance is
      the swarm boundary; isolation by multiple instances.
- [x] ADR 0008 records the decision and supersedes ADR 0006's scope reasoning.
- [x] `docs/architecture.md`, `docs/context.md`, `README.md`, `contracts/protocol.md`,
      `contracts/cli.md`, and `contracts/session.md` drop the self-and-descendants language.
- [x] The docs state the trade: any caller in an instance can interfere with any session,
      exactly as a human with the harness can. Attribution makes it visible; conventions and
      instance separation are the mitigations.

## Tests

- [x] `scope.test.ts` becomes `addressing.test.ts`: cross-tree send/read/wait/cancel/close,
      list-all, and attribution.
- [x] Update list/inputs/lifecycle/dashboard expectations for the flat list and new footer.
- [x] Keep the four acceptance assemblies green; delegation no longer depends on enforced
      scope.
- [x] A stale caller can still address and control sessions; the action is attributed to its
      id.

## Out of scope

Resume and detached descriptors (next milestone), swarm objects, roles, per-session ACLs,
plugin enforcement, cross-instance addressing.

## Acceptance

- `npm run check` clean; all tests green; protocol 2.0 in `hello`.
- A session spawned by one root can address a session in another tree in the same instance,
  and the action carries `by` = the caller.
- Two instances with different homes cannot see each other's sessions.
