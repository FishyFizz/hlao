# Milestone 0.13 — Fleet observation and bulk operations

**Branch:** `dev`
**Baseline:** `c4e3cd5` (the last 0.12 commit)
**Source:** `FEATURE-REVIEW.md` R-15, R-17, R-18, R-21, R-22, R-23, R-25, and R-29.

## Theme

The fleet is observable only one session at a time. `read` follows one id, `list --watch`
redraws state but emits no events, `find` prints raw JSON, `export` saves one session, and
`list --json` carries every static provider option. At the size this tool is for — a job with
several workers — the operator's first job is to notice the worker that needs attention, and
the second is to do something with the whole instance before it goes away.

0.13 closes those gaps with caller-owned projections over the primitives that already exist:

- `hlao watch` merges the live event streams of every session in scope.
- `read` and `find` gain time bounds, regular expressions, and context neighbors.
- `export --all` and `down --export` make a whole-instance backup the default recovery step.
- `hlao usage` aggregates the cost snapshots sessions already carry.
- `list` adapts to the terminal and can project its own JSON; `find` renders a readable line.
- A title-less session falls back to its first prompt instead of a bare handle.

Nothing here creates a second authority. The supervisor still owns sessions and the bounded
log; the client owns the loops, cursors, merging, and rendering.

## Decisions

### D1. Watch is a client, not a supervisor feature

`hlao watch` holds one fleet subscription (chunked to the wire's 100-id limit), keeps a
per-session cursor, and resubscribes when a session appears or disappears. A session present
at start is followed from its current cursor; a session discovered mid-stream is attached
from seq 0 so its first prompt and turn are not lost. The supervisor gains no timer, index,
merge buffer, or watch method. A dropped stream is reconnected with the same cursors.

### D2. Search is a filter, not an index

`ReadParams` gains `afterAt`, `beforeAt`, `regex`, and `context`. They scan the retained log
inside `EventLog`. `context` adds neighbors around matches and reports `matchedSeqs`; `limit`
still bounds matches. Page cursors advance by matches, so a neighbor may repeat on the next
page. `find` reuses the same filters and reports its caps and per-session errors instead of
silently shortening the result.

### D3. Export is a backup, never a clobber

`export --all --out DIR` writes `<id>.json` (or `.jsonl`) plus `manifest.json`, with
per-session counts, truncation, and failures. It refuses to write into a directory that
already holds an export. `down --export DIR` runs the same export before shutdown and refuses
to stop when any session fails; `--force` does not override that promise.

### D4. Output projection stays on the client

`list --fields` selects human columns; `--compact` omits `modes` and `configOptions` from
`list --json` items; `--no-cwd` drops CWD. In a TTY the table drops optional columns (CWD
first) and shortens long cells to fit; piped output keeps full width. `sessions.list` itself
is unchanged because the dashboard reads those fields from list views.

### D5. Usage is derived and honest

`hlao usage` projects the latest snapshot each session carries, or the latest `usage` event
per session inside `--since`/`--until`. Cost is additive per currency and totalled; context is
a per-session snapshot and is never summed. Grouped views therefore show sessions and cost
only. This is observation, not a budget.

### D6. First prompt is display-only

`SessionView.firstPrompt` is a bounded, one-line preview (120 characters) recorded when the
first prompt is sent. It is used only after an operator name and a provider title; it is not
an addressable name. A session with no prompt has `null`.

### D7. Protocol 2.8 is additive

New capabilities `read.time`, `read.regex`, `read.context`, and `session.firstPrompt`; new
`ReadParams.afterAt`, `beforeAt`, `regex`, and `context`; `ReadResult.matchedSeqs`; and
`SessionView.firstPrompt`. A 2.7 client ignores all of it. Release version: 0.13.0.

## Wire changes — protocol 2.8 (additive)

```ts
// ReadParams
afterAt?: string;
beforeAt?: string;
regex?: boolean;
context?: number;

// ReadResult
matchedSeqs?: number[];

// SessionView
firstPrompt?: string | null;
```

New capabilities: `read.time`, `read.regex`, `read.context`, `session.firstPrompt`.

## Out of scope

- A supervisor-side watch loop, search index, merged store, or usage database.
- Shrinking `sessions.list` by default; the dashboard reads static provider options from it.
- A scheduler, DAG, task store, or job registry.
- A budget or stop-at-threshold loop (N-11). `hlao usage` only observes.
- Provider continuity hardening RF-02 through RF-08 and the safety set N-08/N-10/N-11/R-14.
- Replaying history in `watch`; use `read` or `export`.

## Acceptance

- A session spawned after `hlao watch` starts produces labelled events without the caller
  re-listing or restarting the watch.
- `down --export DIR` produces a manifest that replays every retained session, and stops
  without shutting down when a session cannot be exported.
- `list --wide --usage` fits a 120-column TTY by default, while piped output keeps full width.
- `list --json --compact` is materially smaller than the default and still carries usage.
- `find` prints time, session label, seq, type, and a one-line snippet with an ellipsis.
- A title-less session shows its first prompt rather than a bare id.
- `hlao usage --root` totals cost per currency and never sums context snapshots.
- Protocol 2.8 is additive; existing 2.7 clients and the full suite remain green.
