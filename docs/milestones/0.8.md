# Milestone 0.8 — The agent at birth

**Branch:** `milestone/0.8-agent-at-birth`
**Baseline:** HLAO 0.7.0 (`fa9b385`, `milestone/0.7-truthful-surface`)
**Source:** the pruned ledger in `FEATURE-REVIEW.md`, plus the 0.8 scope review.

## Theme

A spawned agent is a user of the harness. It should know the harness at birth, delivery
should survive a retry, and "stop" should stop the work the agent started. The guiding
principle from the scope review:

> **The prompt is the only context channel. HLAO passes references, not payloads.**

HLAO carries orchestration text and state. Files, images, ledgers, and specs are named by the
operator (verbatim or by reference) and read with the agent's own tools. The harness does not
invent a context-injection path and does not become a content bus.

## Decisions

### D1. The birth artifact is a skill, not a brief

`skills/hlao/SKILL.md` ships with the package: frontmatter (`name`, `description`) plus
progressive sections. It is copied to `<HLAO_HOME>/skills/hlao/SKILL.md` so every session has a
stable path, and exposed as `HLAO_SKILL` and `HLAO_SKILL_VERSION`. `hlao skill` prints it;
`hlao skill path` prints the home path; `hlao skill --json` returns metadata and the path.

The first prompt that actually runs gets a separate leading text block:

```
HLAO skill: read $HLAO_SKILL (or run "hlao skill") before acting.
Context is whatever this prompt says, verbatim or by reference; do not invent it.
HLAO carries orchestration text, not file payloads.
```

The pointer is on by default; `spawn --no-skill` disables it. The env and file remain. The
pointer is a separate ACP text block, so the operator's prompt is never rewritten.

### D2. The skill encodes the context and payload rules

The skill tells the agent, in its own words:

- Everything needed is in the prompt, verbatim or as a named reference. If a ledger, spec, or
  file is named, read it. If it is not named, ask; do not infer paths, facts, or state.
- When delegating, pass context the same way: verbatim or by reference. Do not assume the
  child can see the parent's context, and do not invent a shared-state mechanism.
- HLAO carries orchestration text, not payloads. Reference files and images by path; use the
  agent's own file tools and vision.
- The moves and the worker loop; how to report to `HLAO_PARENT_ID`; wait for permission
  instead of hanging.
- Do not move the permission gate; report a blocker. (A norm, not enforcement.)

There are no `--context`/`--ledger` spawn flags and no attachments. Those were rejected: they
invent a context/payload channel the product does not need.

### D3. `whoami` reports the live session

When `HLAO_SESSION_ID` is set, `whoami` probes the supervisor with autostart disabled. If the
session is live, it reports `live: true`, `liveName`, and `nameStale`; if not, `live: false`
with the environment values. `HLAO_NAME` remains birth-time by definition; the live name is
the current label. No supervisor is started by `whoami`.

### D4. Delivery is retry-safe and identity-bearing

- Every send/spawn prompt gets a generated `messageId` (`msg-` + 8 chars), returned even when
  queued. `prompt.sent`, `prompt.queued`, and `prompt.discarded` carry it; queue items expose
  it as `id`; `queue drop --id` targets it.
- An optional `idempotencyKey` dedupes within the live session: 1 hour / 256 keys, evicting
  the oldest. A duplicate returns the original `messageId` plus the current queued/active
  state; it never enqueues again.
- `spawn` accepts an `idempotencyKey`; a duplicate within the same window returns the existing
  session and its first-prompt `messageId` instead of spawning. If the original session is no
  longer in the live table, the key is released and a new spawn is allowed.
- `SendResult.outcome` is `completed`, `cancelled`, or `timed_out`. A queued message cancelled
  before it runs is `cancelled`, not a silent success.

### D5. `createdBy` is provenance, not memory

Spawn records who requested it (`operator` or a session id) in `SessionView.createdBy` and
`session.created`. It is a field, not a recall UI: an important session is remembered by the
agent's context; only completed, low-reuse sessions are forgotten. No stale-caller warning is
in this milestone; reachability is still under discussion.

### D6. POSIX adapters get their own process group

On POSIX, adapters are spawned detached (their own process group). Graceful close signals the
group, and force close/down signals it with `SIGKILL`. Windows keeps the existing
`taskkill /T` path. A POSIX test uses the fake agent's child-process mode and is skipped on
Windows.

## Workstream A — The agent at birth

- [ ] `skills/hlao/SKILL.md` with frontmatter and the D2 rules.
- [ ] `src/skill.ts`: packaged path, home copy, `ensureHomeSkill(home)`, `skillText()`.
- [ ] Supervisor start ensures `<HLAO_HOME>/skills/hlao/SKILL.md` matches the packaged skill.
- [ ] Session injects `HLAO_SKILL` and `HLAO_SKILL_VERSION`; the first prompt gets the pointer
      unless `spawn --no-skill`.
- [ ] `hlao skill`, `hlao skill path`, `hlao skill --json`.
- [ ] `hlao whoami` live lookup (`live`, `liveName`, `nameStale`) without autostart.
- [ ] Help and README point agents at `hlao skill`.

## Workstream B — Retry-safe delivery

- [ ] `messageId` generated for every prompt; echoed in results, events, and queue items.
- [ ] `idempotencyKey` on send/spawn with the D4 window and duplicate semantics.
- [ ] `queue drop --id` (wire `messageId`, exclusive with `position`).
- [ ] `SendResult.outcome`.
- [ ] Spawn's first prompt returns its `messageId`.

## Workstream C — Provenance and stop

- [ ] `SessionView.createdBy` and `session.created.createdBy`.
- [ ] POSIX process group spawn/signal; graceful and forced paths; Windows unchanged.
- [ ] POSIX test with `FAKE_MODE=spawn-child`; skip on Windows.

## Workstream D — Reliability tail

- [ ] `list --mine` (the caller's root subtree; requires `HLAO_SESSION_ID`/`HLAO_ROOT_ID`).
- [ ] Windows backend readiness distinguishes spawnable from a command shim (`.cmd`/`.ps1`),
      with a reason.
- [ ] `spawn --wait` failure prints a `read`/`close` recovery hint.
- [ ] `spawn --wait`/`send --wait` timeout prints bounded partial text (when present).

## Wire changes — protocol 2.3 (additive)

```ts
// delivery
SendParams.messageId?: string;
SendParams.idempotencyKey?: string;
SendResult.messageId: string;
SendResult.outcome?: "completed" | "cancelled" | "timed_out";
QueueItemView.id: string;
QueueDropParams.messageId?: string;   // exclusive with position

// spawn
SpawnParams.idempotencyKey?: string;
SpawnParams.skill?: boolean;          // default true
SpawnResult.messageId?: string;       // the first prompt, when one was sent
SpawnResult.duplicate?: boolean;
SpawnResult.createdBy?: string;       // same value as SessionView.createdBy

// provenance
SessionView.createdBy: string | null;
```

Capabilities: `send.messageId`, `send.idempotency`, `spawn.idempotency`, `spawn.createdBy`.
No attachment, context, or payload fields.

## Tests

- Skill: the file exists, `hlao skill` prints it, `--json` returns metadata, the home copy is
  current, `HLAO_SKILL` points at it, the first prompt carries the pointer, `--no-skill`
  suppresses it, and the pointer is not repeated on later sends.
- `whoami`: live name after a rename; `live:false` with a stale id; it never autostarts.
- Delivery: `messageId` on queued and completed sends; queue drop by id; a repeated
  idempotency key does not duplicate; spawn dedupe returns the same session; a cancelled queued
  message reports `outcome: "cancelled"`.
- `createdBy` for operator and session callers.
- POSIX process group: the adapter's child is gone after force close (skipped on Windows).
- Tail: `list --mine`, Windows shim readiness, spawn-wait recovery/partial text.
- Full unit, e2e, and acceptance suites stay green; protocol 2.3 in `hello`.

## Out of scope

- Attachments/content blocks and `--context`/`--ledger` (rejected by the scope review).
- The stale-caller warning; reachability discussion first.
- Scoped-client enforcement, permission rules, bounds/budget → 0.9.
- Resume after a crash (P0-14) → its own milestone.
- Surfaces (dashboard/TUI/MCP) and the 0.6 transport policy → the 1.0 track.
- Native skill installation into `~/.claude/skills`; the neutral env/pointer path is the 0.8
  contract.

## Acceptance

- A fresh child can read `$HLAO_SKILL` or run `hlao skill` and knows the moves, the context
  rule, and the payload rule without the operator explaining the harness.
- A retried send/spawn with the same key does not duplicate work; message ids are stable and
  visible in results, events, and the queue; a cancelled queued message is not reported as a
  completed turn.
- Spawn results name the requester.
- `close --force` and `down` take the adapter's process group on POSIX.
- `npm run check` clean; all suites green; no new authority, timer, store, or registry.
