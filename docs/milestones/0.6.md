# Milestone 0.6 — The wire is a stream

**Branch:** `milestone/0.6-stream-contract`
**Baseline:** HLAO 0.5.0 (`64e7ae6`)
**Source:** the dashboard feasibility review and ADR 0009.

## Theme

The supervisor protocol is defined over **frames on a stream**, not over a socket
implementation. `contracts/stream.md` states the frame contract: one JSON object, ordered,
reliable, bidirectional, boundary-preserving, bounded. A transport adapter maps that contract
onto a concrete channel. Named pipe and Unix socket remain the default; TCP, TLS, and
WebSocket become additions rather than rewrites.

Two ideas that are deliberately separate:

- **Transport swap** — the same frames over another channel. This milestone implements the
  seam and proves it with a TCP adapter. On its own it is an implementation change, not a wire
  change.
- **Stream semantics** — a persistent connection that multiplexes requests and carries
  server-initiated notifications. This is additive protocol 2.1 work; the 2.0 one-shot
  lifecycle remains.

The token remains local-IPC authority. A transport does not inherit that authority by being
implementable; each transport declares its own authentication model. A browser never receives
the supervisor token.

## Layer 1 — Transport adapter (done)

- [x] `src/stream.ts`: `StreamTarget`, `WireStream`, `WireStreamServer`, incremental NDJSON
      framing, `FrameTooLargeError`, `connectStream`, `createWireServer`.
- [x] Path target (named pipe / Unix socket) and TCP target adapters.
- [x] The supervisor listens and accepts through `WireStreamServer`; `stop()` terminates
      streams and closes the listener through the adapter.
- [x] The client connects, frames, and times out through `connectStream`.
- [x] The liveness probe in `lock` uses `connectStream`; startup and recovery behavior is
      unchanged.
- [x] `src/stream.ts` is the only core module that imports `node:net`.
- [x] Protocol stays `2.0`. Frames, lifecycle, errors, and the 15 s first-frame bound are
      unchanged, so this is an implementation change, not a wire change.

## Layer 2 — Persistent streams (done)

- [x] `hello` with `stream: { persistent: true }` keeps the connection open; every later
      frame is a request correlated by `id`, and responses may arrive out of order. The first
      frame gates the connection, so pipelined frames are queued until the hello reply.
- [x] Every request still carries the token; persistence does not weaken per-frame
      authentication. One connection may change `callerSessionId` per request, as in 2.0;
      clients should keep it stable.
- [x] Notifications are additive frames (`type: "notification"`) while responses keep their
      2.0 shape. Capabilities `stream.persistent`, `stream.subscribe`, `stream.resume` are
      advertised; protocol minor becomes 2.1.
- [x] `stream.subscribe`: `sessionIds?`, `fleet?`, `since?` → a subscription id plus current
      views, cursors, and truncation. Server notifications fire at the same append point that
      notifies waiters; the supervisor gains no timer.
- [x] `stream.unsubscribe`.
- [x] Resume: `since` per session replays from `seq > since`, or reports `truncated`.
- [x] Bounded outbound buffer: a consumer that lets more than 8 MiB sit in the transport is
      closed and re-syncs by cursor. It never blocks the session table or appends.
- [x] At most 64 in-flight requests per connection; further requests get
      `too_many_requests` and the connection stays open.
- [x] The legacy one-shot path is unchanged. The CLI does not switch to persistent
      connections.

## Transport policy (partly done)

- [x] `contracts/stream.md` states the policy: enabled targets, binding, credential, and
      threat notes per transport. The supervisor token is local-IPC authority, not a network
      or browser credential.
- [ ] Loopback TCP is opt-in configuration with the supervisor token; it is not bound by
      default.
- [ ] Non-loopback transports require TLS and a credential that is not the supervisor token.
- [ ] WebSocket adapter in a separate package, with an origin allowlist and an operator-minted
      one-time code exchanged for a short-lived cookie. The supervisor token never reaches the
      page.

## Out of scope

Server push in 2.0, any default network binding, multi-instance aggregation in one connection,
and the dashboard's view model or rendering.

## Acceptance

- `npm run check` clean; all unit, e2e, and acceptance tests green.
- `hello` reports protocol `2.1`; the 2.0 one-shot path is unchanged and every existing e2e
  test passes without modification.
- The supervisor, client, and lock modules contain no direct `node:net` import.
- A test server and client exchanging frames over a TCP target prove the adapter seam.
- A raw persistent client can negotiate, multiplex requests, subscribe to the fleet and to a
  session, receive view and event notifications, resume from a cursor, unsubscribe, and see a
  removed session reported once.
- The in-flight cap rejects excess requests with `too_many_requests` without closing the
  connection.
