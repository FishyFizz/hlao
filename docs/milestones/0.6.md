# Milestone 0.6 — The wire is a stream

**Branch:** `milestone/0.6-stream-contract`
**Baseline:** HLAO 0.5.0 (`64e7ae6`)
**Source:** the dashboard feasibility review and ADR 0009.

## Theme

The supervisor protocol is defined over **frames on a stream**, not over a socket
implementation. `contracts/stream.md` states the frame contract: one JSON object, ordered,
reliable, bidirectional, boundary-preserving, bounded. A transport adapter maps that contract
onto a concrete channel. Named pipe and Unix socket remain the default; TCP, TLS, and
WebSocket become additions rather than rewrites.

Two ideas that are deliberately separate:

- **Transport swap** — the same frames over another channel. This milestone implements the
  seam and proves it with a TCP adapter. It does not change protocol 2.0.
- **Stream semantics** — a persistent connection that multiplexes requests and carries
  server-initiated notifications. This is additive 2.1 work and is not required for the
  transport seam to pay off.

The token remains local-IPC authority. A transport does not inherit that authority by being
implementable; each transport declares its own authentication model. A browser never receives
the supervisor token.

- [x] `src/stream.ts`: `StreamTarget`, `WireStream`, `WireStreamServer`, incremental NDJSON
      framing, `FrameTooLargeError`, `connectStream`, `createWireServer`.
- [x] Path target (named pipe / Unix socket) and TCP target adapters.
- [x] The supervisor listens and accepts through `WireStreamServer`; `stop()` terminates
      streams and closes the listener through the adapter.
- [x] The client connects, frames, and times out through `connectStream`.
- [x] The liveness probe in `lock` uses `connectStream`; startup and recovery behavior is
      unchanged.
- [x] `src/stream.ts` is the only core module that imports `node:net`.
- [x] Protocol stays `2.0`. Frames, lifecycle, errors, and the 15 s first-frame bound are
      unchanged, so this is an implementation change, not a wire change.

## Layer 2 — Persistent streams (planned)

- [ ] A persistent connection accepts many request frames, correlated by `id`; responses may
      be out of order. One connection is one caller (`callerSessionId`) and one token check at
      open.
- [ ] Add a frame discriminator without breaking 2.0: a request with no `type` keeps the
      one-shot path. Advertise `stream.persistent` in `hello.capabilities`.
- [ ] `stream.subscribe`: `sessionIds?`, `fleet?`, `since?` → a subscription id plus current
      views and cursors. Server notifications fire at the same append point that notifies
      waiters; the supervisor gains no timer.
- [ ] `stream.resume`: reconnect replays from `seq > since`, or reports `truncated`.
- [ ] Bounded per-connection send queue. A slow consumer is closed and re-syncs by cursor; it
      never blocks the session table or appends.
- [ ] Per-connection in-flight request limit. A wedged connection cannot grow core memory
      without bound.
- [ ] Keep the legacy one-shot path. The CLI does not switch to persistent connections.

## Transport policy (planned)

- [ ] `contracts/transports.md` or a section in the stream contract: enabled targets, binding,
      credential, and threat notes per transport.
- [ ] Loopback TCP is opt-in configuration with the supervisor token; it is not bound by
      default.
- [ ] Non-loopback transports require TLS and a credential that is not the supervisor token.
- [ ] WebSocket adapter in a separate package, with an origin allowlist and an operator-minted
      one-time code exchanged for a short-lived cookie. The supervisor token never reaches the
      page.

## Out of scope

Server push in 2.0, any default network binding, multi-instance aggregation in one connection,
and the dashboard's view model or rendering.
