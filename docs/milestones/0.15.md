# Milestone 0.15 — Provider-owned permissions and the operator relay

**Branch:** `dev`
**Baseline:** `d3a5837` (the 0.14 steering commit)
**Source:** `FEATURE-REVIEW.md` N-08, N-10, R-14, and the 2026-10-21 permission-model
review. ADR 0013 supersedes the policy mechanism in ADR 0004.
**Release:** 0.15.0 · wire protocol **3.0** (breaking)
**Frozen wire:** `docs/milestones/0.15-protocol.md` (authoritative; changes need approval)
**ADR:** `docs/adr/0013-provider-owns-permission-policy.md`

## Theme

HLAO currently runs a second permission policy beside the provider's native mode. The two
overlap and disagree: the provider knows its tools and modes, while HLAO sees only ACP
requests and a tri-state. Per-tool rules, deny-always, handler routing, and policy
inheritance all tried to rebuild what the provider already owns.

0.15 removes the duplicate layer and replaces it with a relay:

- **The provider's mode is the coarse policy.** Operators set a per-backend `defaultMode`;
  an operator spawn or a live `mode` change overrides it. Agents cannot choose a mode.
- **Every provider ask is forwarded to the operator.** The supervisor parks the ACP request
  and exposes it; the operator answers with the provider's own options via `permit`.
  There is no auto-allow and no auto-deny.
- **A bounded pending queue** replaces the one-pending auto-cancel, so parallel tool calls
  are individually answerable.
- **A one-shot timeout** bounds the operator wait and fails closed.

The provider owns permission semantics. HLAO relays, records, and bounds. No scheduler, no
policy engine, no handler graph, no per-tool rule language.

## Decisions

### D1. The provider owns permission policy

`permissionPolicy` and its `allow|ask|deny` behavior are removed. The provider's native mode
(`session/set_mode`) is the policy layer; the ACP request is the event. HLAO answers only
when the operator answers.

### D2. Control is operator-only

An operator shell (no `HLAO_SESSION_ID`) or the dashboard may:

- answer a pending request (`sessions.permit`),
- change a session's provider mode (`sessions.set_mode`),
- pass `--mode` at spawn.

An agent caller is refused with `operator_only` for all three. Reads remain open: an agent
may read its mode and its pending requests, but it cannot answer them or change the mode.
The skill says so explicitly.

The operator is the only answerer. A parent agent cannot unblock a child; it reports the
blocker. An operator typing inside an agent's terminal is the agent as far as the CLI is
concerned; the operator uses a separate shell or the dashboard.

### D3. A per-backend operator default mode

`BackendManifest.defaultMode?: string` is added to user and project backend manifests. The
operator's explicit `--mode` at spawn wins, then the backend default, then the provider's
own default. Agent-spawned children use the backend default; an agent-supplied `--mode` is
refused. The operator can change a live session with `hlao mode <id> <mode>`.

Modes are backend-specific and are not inherited across backends. The operator's
`defaultMode` is the portable anchor; the provider's default is the fallback. This is the
replacement for policy inheritance.

### D4. A bounded pending queue

`#pending` becomes a FIFO map keyed by request id. `SessionView.pendingPermissions` replaces
the singular `pendingPermission`. `maxPendingPermissions` (default `16`, range `1..1000`) is
captured at spawn.

- A second concurrent request is queued, not cancelled.
- When the queue is full, the new request is answered `cancelled` and recorded as
  `permission.resolved { by: "system", reason: "queue_full", optionId: null }`. It is not
  enqueued.
- `permit --request <id>` answers one; `--all-pending` answers every pending request.
- Without `--request`, a session with more than one pending is a `bad_request` that names
  the ids.
- A provider withdrawal clears only its own request. `cancel`/`close` clear all.
- `wait --until permission` and `list --pending` match any pending.
- The prompt queue is separate and keeps its own `MAX_QUEUED_PROMPTS`.

### D5. A one-shot permission timeout

`permissionTimeoutMs` (user config, default `30 * 60_000`, `0` = park) starts one absolute
deadline at `requestedAt` per request. The timer is cleared on answer, provider withdrawal,
or close. At expiry:

- select `reject_once`, else `reject_always`, else cancel;
- never select an allow option;
- record `permission.resolved { by: "timeout", reason: "timeout", optionId }`.

The value is captured at spawn (live sessions keep their value; `reload` affects new
sessions). It is operator config; there is no spawn flag and no agent control. One-shot
deadlines are already used by `withTimeout`; no recurring timer is introduced.

### D6. `--always` is a provider option selector

`permit --allow --always` selects the provider's `allow_always` option; `--deny --always`
selects `reject_always`. If the provider does not offer it, the command fails with
`bad_option` rather than falling back or mutating HLAO state. `--always` no longer changes a
policy. This resolves N-10's deny-always gap.

### D7. Protocol 3.0, no compatibility shim

Removing `permissionPolicy`, `sessions.set_policy`, and `policy.changed` is a breaking wire
change. The major moves to 3.0; the dashboard is updated in the same milestone; there is no
inert field or deprecated method. Pre-1.0 is the time to remove.

### D8. A live supervisor of another major is never treated as a crash

`probeSupervisor` gains a result that distinguishes "not answering" from "alive, speaking
major N." `client.ensureLock` and `Supervisor.#acquireLock` must refuse to clobber a live
supervisor with a different major and report `version_mismatch` with the upgrade
instructions. The operator stops the old supervisor with the old CLI (or `down` if the
legacy connection path is used) before starting 0.15.

### D9. Advisory, not containment

Caller identity is still self-declared from `HLAO_SESSION_ID`, and the instance token is
readable by same-user agents. The operator-only checks close the normal paths (`policy
--self`, `permit --self`, `mode --self`, an agent `--mode`) but are not an ACL. The docs and
skill state this. N-08's scoped credential or a separate instance remains the containment
path.

### D10. Elicitations are out of scope

Provider elicitations are not allow/deny permissions and keep their current rule: they wait
for an operator or a delegated session. Applying the operator-only relay to elicitations is
a separate decision.

### D11. Provider-specific semantics are accepted

HLAO does not add per-tool rules. The provider mode and the provider's own configuration are
the rule layer. Differences between backends are exposed through `modes` and
`configOptions`, not normalized. N-10's per-tool-rules item becomes a product decision:
delegated to the provider.

## Wire changes — protocol 3.0 (breaking)

```ts
// Removed
PermissionPolicy;
SessionView.permissionPolicy;
SessionView.pendingPermission;
SpawnParams.permissionPolicy;
SetPolicyParams; SetPolicyResult; "sessions.set_policy";
"policy.changed";
permission.requested.policy; permission.requested.auto;
PermitParams.always;

// Added
SessionView.pendingPermissions: PermissionView[];
PermitParams.requestId?: string;
PermitResult.requestId: string;
permission.requested.queuePosition?: number;
AgentView.defaultMode?: string;

// New capabilities
"session.pendingPermissions";
"permit.request";
```

`permission.resolved` keeps `requestId`, `optionId`, `optionName`, `by`, `reason`, and
`note`. New `by`/`reason` combinations: `by: "operator"`, `by: "timeout"`,
`by: "system"` with `reason: "queue_full"` or `"withdrawn"`.

## Config changes

```jsonc
{
  "permissionTimeoutMs": 1800000,   // 30m; 0 = park
  "maxPendingPermissions": 16,      // 1..1000
  "backends": {
    "claude": { "defaultMode": "auto" }
  }
}
```

- Removed: `permissionPolicy`.
- Added: `permissionTimeoutMs`, `maxPendingPermissions`, per-backend `defaultMode`.
- `defaultMode` is accepted in user and project backend manifests. Unknown mode names are
  left to the adapter; the spawn reports the adapter's error.

## Migration

1. Stop the running supervisor before upgrading (`hlao down` with the old CLI, or the legacy
   `down` path decided in E). A 3.0 client refuses to replace a live 2.x supervisor.
2. Remove `permissionPolicy` from `config.json`; add `permissionTimeoutMs` if the default is
   not wanted. Set `backends.<name>.defaultMode` for unattended runs.
3. Replace `--permission allow` with the backend default mode or an operator `--mode`.
   Replace `--permission ask` with a provider mode that asks plus the operator relay; there
   is no HLAO gate to configure.
4. Replace `hlao policy ...` with `hlao mode ...`. `permit --always` now selects the
   provider's always option.
5. Update agent sessions with the new skill: an agent cannot set a mode or answer a request.
6. Update the dashboard to 3.0.
7. Update acceptance examples that passed `--permission` or relied on the `allow` default.

## Out of scope

- N-11's general bounds (`maxSessions`, configurable prompt-queue caps, byte bounds). The
  permission queue bound is specific to this milestone.
- N-08's scoped credential or separate-instance containment. The operator-only checks are
  advisory.
- RF-01 through RF-08 (provider continuity hardening).
- Per-tool permission rules; the provider owns them.
- Elicitation relay or operator-only elicitation.
- Budgets, schedulers, DAGs, policy engines, or a global registry.
- Provider mode normalization across backends.
- A dashboard redesign beyond the 3.0 projection and operator controls.

## Acceptance

- A provider permission request always reaches the operator; no policy answers it silently.
- An agent cannot answer a request or change a provider mode; the operator can do both from
  an operator shell or the dashboard.
- An agent-spawned child runs in the operator's per-backend default mode; the operator can
  override it live.
- Two parallel permission requests are both visible and answerable; neither is silently
  cancelled. A full queue is visible and fails closed.
- An unanswered request is rejected or cancelled at the deadline, with `by: "timeout"`; `0`
  parks.
- Protocol 3.0 is a deliberate break: the removed policy surface fails with a migration
  message, and a live 2.x supervisor is reported, not replaced.
- The dashboard, full suite, and `npm run check` are green.
