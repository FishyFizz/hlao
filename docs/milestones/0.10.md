# Milestone 0.10 — Truth before features

**Branch:** `milestone/0.10-truth-pass`
**Baseline:** HLAO 0.9 (`249a84a`, `milestone/0.9-maintenance`)
**Source:** `FEATURE-REVIEW.md` (the 0.10 review was merged into the ledger and deleted after
this milestone), selection review.

## Theme

The 0.10 review found the primitive surface sound and the supervisor unusually well
instrumented, but the records operators and agents act on still lie in P1 ways: `read` says
every prompt came from `you`, `wait` exit codes contradict the documented conditions, a
malformed config starts an empty instance instead of failing, a supervisor crash erases the
table without a signal, and the skill's first worker-loop command deadlocks an agent against
its own turn.

This milestone finishes the truth pass 0.7 started. It is deliberately the last pass that can
be done without deciding what HLAO asks providers to expose: every selected item either
renders data already on the wire, removes a false claim, or records an action HLAO already
takes. It adds no scheduler, store, registry, timer, or second authority. The only wire
change is additive truth metadata (protocol 2.4).

### Why not safety and policy

`docs/milestones/0.9.md` recorded that N-08 enforcement, N-10, and N-11 move to 0.10. This
selection supersedes that note.

The 0.10 review is newer evidence. Nine of its top eleven findings are truth and guidance,
and this milestone takes all nine; the two provider-state findings are deferred to 0.11.
Safety remains important, but it is the one remaining L-sized design cluster:
a scoped client credential (N-08), per-tool rules plus a pending-request queue (N-10), and
instance/session bounds plus a budget stop condition (N-11). Each needs a product decision
about authority, and together they would dominate a milestone that can otherwise close eight
P1 lies at S cost.

There is also an ordering argument. The safety work adds enforcement and audit. If the
operator's transcript still says `you` for a sibling's prompt and omits who closed a session,
the new controls inherit a lying audit trail. Fixing attribution, queue identity, and crash
signalling first makes the safety milestone reviewable. R-01 is the audit half of N-08;
enforcement stays in the safety milestone.

## Decisions

### D1. Actor fields are rendered, never inferred

The renderer stops hardcoding `you`. The actor label is `operator` for the operator and
`from <id>` for a session, matching the JSON `from`/`by`/`createdBy` values. Selected shapes:

- `prompt.sent` → `operator › …` or `from nx6jss › …`.
- `prompt.queued` → `queued msg-… · from <actor> · "<bounded preview>" (position N)`.
- `prompt.discarded` → `discarded msg-… · from <actor> · "<bounded preview>" (<reason>)`.
- `session.created` → `session created · <backend> · <cwd> · by <actor>`.
- `session.closed` / `session.failed` / `cancel.requested` / `session.renamed` → show `by`.

Previews use the same bounded, whitespace-collapsed `previewText` as `queue` and are
sanitized at the render boundary. `createdBy` appears in the `read` header, `get`, and
`list --wide`. Human/JSON parity is tested per actor-bearing event; a test that only checks
the human line is insufficient.

### D2. `wait` has one condition table

The wire semantics do not change. `settled` is satisfied by idle with an empty queue, by a
permission stop, or by a terminal session. The human path returns the computed exit code it
already used for JSON:

| Condition | Resolves when | Terminal session | Exit |
|---|---|---|---|
| `settled` | settled, permission, or exit | satisfied | 0 |
| `idle` | the historical completion alias for `settled` | unsatisfied | 0 while running; 3 after terminal |
| `permission` | a request is pending | unsatisfied | 2 on timeout; 3 after terminal |
| `exit` | terminal | satisfied | 0 |

A terminal session before the requested condition is unsatisfied and returns 3, except
`settled` and `exit`, where termination is completion. `--fail-if-failed` also returns 3 for
a failed session, and a timeout returns 2.

`idle` remains an alias, not a second wire concept. `help wait` and the README say exactly
that: "no runnable turn: finished, parked at a permission gate, or ended", with the terminal
exception above. A permission stop displays `settled (permission)` and explains the `permit`
command; it is not reported as a clean idle. A caller that needs a clean turn boundary uses
`--until change --type turn.ended` or `get`. No `--until done` is added in 0.10.

Single-target and multi-target human paths use the same code.

### D3. Startup fails; crashes are recorded

A supervisor that cannot parse or validate its config does not start. `Supervisor.start()`
raises `config_invalid` before acquiring the lock or listening; the autostarting command
prints the parse error, suggests `hlao config validate` / `hlao doctor`, and exits 1. The
old degraded mode is removed. `hello.configError` stays in the type for older supervisors
and the `status` print branch stays, but 0.10 no longer sets it. This also resolves
P2-0.5-18: `status --start` with an invalid config no longer exits 0.

A stale lock is evidence, not litter. When `#acquireLock` reads a lock whose pid is dead (or
whose probe fails) and whose state is `running`/`starting`, it records the old `pid`,
`version`, `startedAt`, and the detection time in `<HLAO_HOME>/last-crash.json` before
removing the lock. The new supervisor exposes it as `hello.lastCrash`; `status --json`
passes it through; `doctor` reports it; the command that autostarted the supervisor prints
one stderr line:

```text
hlao: previous supervisor (pid N) did not shut down cleanly; its live table and retained history were lost
```

There is no recovery claim and no adapter process scan in 0.10. A clean `stop()` removes the
marker; while the new supervisor runs, `status` and `doctor` keep reporting it. The log gets
the same fact, so `logs` remains a usable diagnostic.

### D4. The agent loop distinguishes inside-turn from between-turn

The skill's worker loop is rewritten around the actual constraint: an agent runs one turn
at a time, and a session parked on `session/request_permission` cannot execute a command to
answer itself.

- Inside a turn: `read`, `wait` on *other* sessions, report the blocker in the final message.
- Between turns: a self-send is a deferred next turn. Omit `--wait`, finish the turn, and
  let the queued prompt run.
- A parked permission is answered by the operator or another session (normally the parent);
  the skill says so, and the agent leaves a clear blocker instead of waiting on itself.

The supervisor enforces the one dangerous shape: a self-send with `--wait` while the caller
is the target's active turn returns `bad_request` with the deferred recipe, rather than
timing out after the requested 20 minutes. A self-send without `--wait` still queues, an
idle self-send with `--wait` still works, and an operator/other-session send with `--wait`
to a busy session is unchanged.

The pointer is separated: `skillPointer` ends with a blank line, so an adapter that
concatenates text blocks cannot glue the pointer onto the operator's first words. The first
prompt that runs with the pointer carries `injected: { skill, path, blocks }`.
`#skillInjected` is set only after `session/prompt` resolves; a failed request leaves the
pointer to be sent with the next prompt. `spawn --no-skill` produces neither the pointer nor
the record.

### D5. One version source

`package.json` is the source; `src/version.ts` already reads it. The skill version is the
package version, because the skill ships inside the package. A unit/CI check asserts
`package.json` == the lock root version == `VERSION` == the skill metadata and that
`CHANGELOG.md` has the current version heading. 0.10 bumps the package to `0.10.0` and adds
the missing 0.8.0 and 0.9.0 entries. Historical claims are corrected or annotated, not
silently rewritten.

## Wire changes — protocol 2.4 (additive)

```ts
// hello result, and the status --json pass-through
HelloResult.lastCrash?: {
  pid: number;
  version: string;
  startedAt: string;
  detectedAt: string;
};

// prompt.sent.data on the first injected prompt
injected?: {
  skill: string;   // HLAO_SKILL_VERSION
  path: string;    // HLAO_SKILL
  blocks: number;  // text blocks sent to the adapter
};
```

Capabilities: `supervisor.lastCrash`, `prompt.injected`.

No new methods, no changed method parameters, no new provider/ACP capability advertisement.
The supervisor wire minor moves 2.3 → 2.4; clients feature-detect both fields.

## Tests

- **Actor parity:** `prompt.sent` (operator and sibling), `prompt.queued`,
  `prompt.discarded`, `session.created`, `session.closed`, `cancel.requested`,
  `session.renamed`; human output contains the actor and JSON contains the same value.
- **Queue loss:** after `cancel`, the human transcript still carries the discarded message's
  id, sender, and preview.
- **Wait matrix:** closed, failed, and permission-parked sessions; `settled`, `idle`,
  `permission`, `exit`, and timeout; single and multi target; human and JSON exit codes must
  agree. `--fail-if-failed` remains 3.
- **Get:** every field named in `help get` appears in human output or is marked JSON-only;
  `--brief` prints only the header; JSON shape unchanged.
- **List:** `--cwd` with no match reports "no sessions match the filters" and the true
  instance counts; `--cwd` and `--cwd-prefix` are documented and behave differently.
- **Config:** malformed config makes `list` exit 1 with the parse error and starts no
  supervisor; `config validate` and `doctor` still exit 1; fixing the config starts normally.
- **Crash:** kill the supervisor with a live table; the next command warns, `status --json`
  reports the old pid/start time, `doctor` fails or warns, and the log records the loss.
- **Agent loop:** the skill and README contain no `send --self … --wait` worker-loop line; a
  busy self-send with `--wait` is rejected with the deferred recipe; a busy self-send
  without `--wait` runs after the turn; an idle self-send with `--wait` works.
- **Pointer:** the first prompt's blocks are `[pointer + blank line, text]`; concatenation
  shows the separator; `prompt.sent.injected` has the version/path/block count; a failed
  `session/prompt` does not mark injection and the next prompt resends the pointer;
  `--no-skill` sends neither.
- **Release:** version consistency test; changelog headings; README ACP line; contracts
  command list; `docs/context.md`.
- **Full suite:** `npm run check` clean; unit, e2e, and acceptance suites green; protocol 2.4
  in `hello` with the two new capabilities.
